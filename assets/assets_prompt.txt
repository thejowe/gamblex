# 1. OBJETIVO PRINCIPAL

Debes crear y mantener un sistema de producción de assets para todo el videojuego.

El objetivo final es que:

* todos los assets parezcan creados por el mismo artista;
* todos respeten la misma resolución y pixel density;
* todos utilicen una paleta coherente;
* todos compartan iluminación, materiales y lenguaje visual;
* los assets reutilizables se creen como sistemas y no como imágenes independientes;
* las variantes se generen a partir de assets maestros;
* los assets sean adecuados para producción dentro del motor del juego;
* exista documentación persistente para que no sea necesario volver a explicar estas reglas en futuras sesiones.

NO empieces generando assets inmediatamente.

Primero debes inspeccionar el proyecto y crear la arquitectura de producción.

# PIXELLAB — REGLA OBLIGATORIA

PixelLab es la **herramienta principal y preferente para la creación y edición de todos los assets pixel art del proyecto**.

Claude Code debe utilizar **PixelLab mediante su integración MCP** siempre que la tarea requiera generar, editar, variar, transformar o animar pixel art.

## Jerarquía de herramientas

Utiliza esta prioridad:

1. **PixelLab MCP** → generación y edición de pixel art.
2. **Código/procedimientos del proyecto** → composición de assets repetitivos, variantes, spritesheets y elementos matemáticamente definidos.
3. **Herramientas de edición existentes en el proyecto** → ajustes técnicos y preparación.
4. Otras herramientas → únicamente si PixelLab no puede realizar correctamente una tarea concreta.

NO sustituyas PixelLab por otro generador de imágenes simplemente porque sea más conveniente.

## Regla de consistencia

Si un resultado de PixelLab contradice:

* la paleta;
* el pixel density;
* la iluminación;
* el estilo;
* la escala;
* los materiales;
* el MASTER;

NO lo marques como aprobado.

Debes corregirlo mediante edición/regeneración antes de continuar.

---

## Regla de aprobación

PixelLab genera el **DRAFT**.

Claude Code valida.

El `CasinoArtDirector` decide si cumple el Style Bible.

Solo entonces:

```text
DRAFT
 ↓
REVIEW
 ↓
APPROVED
 ↓
IMPLEMENTED
 ↓
FINAL
```

Nunca consideres que una generación de PixelLab es automáticamente un asset final.

---

## Regla absoluta

**Para cualquier tarea de pixel art, intenta primero resolverla con PixelLab MCP.**

Si PixelLab no es adecuado para esa tarea concreta, explica internamente por qué y utiliza la alternativa más apropiada.

No cambies de herramienta sin motivo.

PixelLab debe ser considerado una parte fundamental del pipeline artístico del proyecto.
